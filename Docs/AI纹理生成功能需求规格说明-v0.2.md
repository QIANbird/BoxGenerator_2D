# AI 纹理生成功能需求规格说明

## 1. 文档信息

- 版本：v0.2
- 状态：本地开发版
- 适用项目：BOXgenerator 3D 宝箱生成器
- 适用界面：`UILayout2.0`
- 当前阶段：本地 Mock 开发与交互验证
- 后续阶段：接入正式云端 AI API
- 需求来源：`AI-需求说明.pdf` 及 2026-07-23 需求澄清

## 2. 功能概述

在现有参数化 3D 宝箱生成器中加入 AI 纹理效果图生成功能。

系统始终将当前 Editing 模式中的彩色 3D 宝箱画面作为“基本型与骨架参考图”。用户还可以上传一张期望纹理或风格参考图、输入文字描述、选择预设风格。系统将这些信息组织为生成请求，由本地 Mock 服务或后续正式 AI 服务生成一张二维效果图。

AI 返回图不作为材质贴回 3D 模型，而是直接显示在 Preview the Texture 区域。返回图需要尽量保持 Editing 参考图中宝箱的视角、大小、位置、轮廓和画面比例，使两个模式切换时主体基本对齐。

## 3. 已确认的产品规则

1. AI 返回结果是一张二维效果图，不贴回 3D 模型。
2. 每次生成都必须发送当前 Editing 模式的彩色宝箱截图。
3. Editing 截图用于约束宝箱基本型、骨架、视角、大小和位置。
4. 用户上传图片是额外的纹理或风格参考，不替代 Editing 截图。
5. 支持纯文字、纯上传图片、纯预设风格，以及任意组合输入。
6. Editing 截图使用用户当前旋转视角，不切换至固定标准视角。
7. Editing 与 Preview the Texture 中的宝箱观察角度必须保持一致。
8. 仅进入 Editing 不会清除 AI 结果；用户实际修改宝箱参数后结果才失效。
9. 生成期间锁定整个主界面。
10. 生成状态提示显示在画面中心。
11. 首版风格只实现 UI 与配置占位，提供“硬核科幻”和“卡通”两个主题。
12. Download 导出当前宝箱预览画面，画面中只要存在宝箱即可下载，不要求已经生成 AI 结果。
13. 下载格式固定为 JPG。
14. 用户旋转宝箱视角不会自动清除或标记旧 AI 结果失效；如需匹配新角度，由用户主动再次点击 Generate Texture。
15. 生成过程中必须提供可取消的模态加载弹窗。

## 4. 产品目标

### 4.1 核心目标

- 为 AI 生图提供可控的 3D 宝箱基本型参考。
- 允许用户以文字、上传图片和预设风格控制纹理效果。
- 保证 AI 二维结果与原始 3D 参考图在构图上尽量一致。
- 提供明确、不可重复提交的异步生成流程。
- 正确处理生成结果与后续参数编辑之间的一致性。
- 支持随时导出当前宝箱预览画面。

### 4.2 本地开发阶段目标

正式 API 到位前，先完成：

- Texture Panel 全部交互；
- Editing 参考图捕获；
- 上传图片读取与预览；
- 预设风格占位；
- 最终提示词组织；
- 本地 Mock 异步服务；
- 可取消的模态加载弹窗；
- 二维结果展示；
- 参数变化后的结果失效；
- JPG 下载；
- 成功、失败和超时测试。

## 5. 术语定义

- Editing 模式：显示彩色 3D 宝箱并允许调节参数、旋转视角的模式。
- Preview the Texture 模式：显示默认宝箱预览或 AI 二维效果图的模式。
- 基本型参考图：点击生成时，从 Editing 模式捕获的彩色宝箱画面。
- 上传参考图：用户从本地选择的纹理或风格参考图片。
- AI 二维效果图：AI 根据基本型参考图、可选上传图和提示词返回的最终图片。
- 默认预览：没有有效 AI 结果时，Preview the Texture 模式显示的宝箱画面。
- 有效 AI 结果：最近一次成功生成，且成功后宝箱参数未发生实际变化的结果。
- 当前预览画面：当前预览区域中实际显示的宝箱图像，可以是默认 3D 渲染画面，也可以是 AI 二维效果图。

## 6. 输入组合规则

### 6.1 始终存在的输入

每次生成请求必须包含：

- 当前 Editing 模式彩色截图；
- 当前宝箱参数快照；
- 当前用户旋转视角；
- 目标输出宽度和高度；
- 系统构图约束提示词。

### 6.2 用户可选输入

以下三项均为可选，并允许任意组合：

- 文字描述；
- 上传纹理或风格参考图；
- 预设风格。

允许的典型组合包括：

- 仅文字；
- 仅上传图片；
- 仅预设风格；
- 文字加上传图片；
- 文字加预设风格；
- 上传图片加预设风格；
- 文字、上传图片和预设风格同时使用。

如果三项用户输入全部为空，则 Generate Texture 不可用，并提示用户至少提供一种生成要求。

## 7. 总体工作流程

1. 用户在 Editing 模式创建、调节和旋转宝箱。
2. 用户进入 Preview the Texture，打开 Texture Panel。
3. 用户按需输入文字、上传参考图或选择预设风格。
4. 用户点击 Generate Texture。
5. 系统捕获用户当前视角下的 Editing 彩色宝箱画面。
6. 系统构建最终提示词和生成请求。
7. 系统显示位于画面中心的模态加载弹窗，并锁定弹窗以外的整个主界面。
8. 本地阶段由 Mock 服务延迟返回测试图片；正式阶段由云端 API 返回图片。
9. 成功后，系统在 Preview the Texture 区域直接显示 AI 二维效果图。
10. AI 效果图应与 Editing 参考图的画布比例、宝箱视角、大小和位置基本一致。
11. 用户进入 Editing 时，如存在有效 AI 结果，系统弹出风险确认框。
12. 用户确认进入 Editing 后，AI 结果暂时保留。
13. 只有当用户实际修改宝箱参数时，AI 结果才失效并被清除。
14. 用户可在预览区域存在宝箱时点击 Download，将当前预览画面导出为 JPG。

## 8. 功能需求清单

### FR-01 Texture Panel

Texture Panel 包含：

- 上传图片区域；
- Reference Style 按钮；
- 多行文字描述输入框；
- Generate Texture 按钮；
- Download 按钮；
- 当前风格显示；
- 错误信息区域。

界面使用 `UILayout2.0`，并保持现有视觉风格。

### FR-02 上传纹理或风格参考图

1. 点击上传区域，打开本地文件选择器。
2. 选择图片后，在上传区域显示缩略图。
3. 上传图只用于表达期望纹理或风格，不用于替代宝箱基本型。
4. 用户可替换或清除已选图片。
5. 非法、损坏或无法读取的文件需要显示错误。
6. 本地 Mock 阶段必须完成真实文件读取，不使用固定假路径。

本地开发暂定：

- 支持 `.jpg`、`.jpeg`、`.png`；
- 保持原始宽高比；
- 缩略图使用 Contain 方式显示；
- 文件大小和像素上限保留为可配置项，待正式 API 限制确定后定稿。

### FR-03 预设风格浮层

1. 点击 Reference Style，在按钮附近打开卡片式浮层。
2. 点击浮层外部或关闭按钮可关闭。
3. 单次只能选择一个风格。
4. Texture Panel 显示当前选中风格。
5. 首版提供以下占位项：
   - No Style；
   - 硬核科幻；
   - 卡通。
6. 每个风格采用独立配置数据，至少包含：
   - ID；
   - 显示名称；
   - 占位缩略图；
   - 附加提示词。
7. 后续可只修改配置与资源，不改动主要 UI 控制逻辑。

首版占位提示词可暂定为：

- 硬核科幻：强调硬表面机械结构、工业金属、科技细节和高对比材质。
- 卡通：强调卡通化材质、简洁色块、柔和明快配色和清晰轮廓。

正式提示词和缩略图后续替换。

### FR-04 文字描述

1. 用户可输入纹理、材质、颜色、图案和其他要求。
2. 支持中文、英文、数字和常用符号。
3. 生成前去除首尾空白。
4. 文字允许为空，前提是用户已经上传图片或选择预设风格。
5. 最大字符数应作为可配置项。

本地阶段建议默认最大长度为 500 个字符。

### FR-05 最终提示词组织

最终提示词由以下部分组成：

`系统基本型与构图约束 + 用户文字 + 预设风格附加提示词`

系统约束至少表达：

- 严格参考第一张宝箱基本型图片；
- 保持宝箱视角不变；
- 保持宝箱轮廓和主要结构不变；
- 保持宝箱在画面中的中心位置、占画面比例和边界范围基本不变；
- 不随意放大、缩小、旋转、平移或裁切宝箱；
- 不增加无关主体；
- 只改变纹理、材质、颜色和表面细节；
- 输出画布宽高和输入基本型参考图一致；
- 如存在第二张用户上传图，仅参考其纹理、配色和风格，不复制其主体结构。

请求数据需要同时保留：

- 用户原始文字；
- 风格 ID；
- 风格附加提示词；
- 系统约束提示词；
- 最终提示词。

### FR-06 Editing 基本型参考图捕获

1. 每次点击 Generate Texture 时重新捕获。
2. 捕获对象为 Editing 模式的彩色宝箱画面。
3. 使用用户当前旋转视角。
4. 不切换到固定视角，也不生成额外视图。
5. 捕获结果对应当前最新宝箱参数。
6. 捕获图不包含按钮、面板、提示文字等 UI。
7. 捕获图需要保留完整宝箱，不得裁切。
8. 捕获失败时停止生成并显示错误。
9. 捕获时不能改变用户在界面中看到的视角。

### FR-07 输入图与输出图尺寸一致性

为提升模式切换时的视觉对齐程度：

1. Editing 捕获图、AI 请求目标尺寸和 Preview the Texture 显示画布使用相同宽高比。
2. 正式 API 支持指定输出尺寸时，请求输出尺寸应与 Editing 捕获图像素尺寸相同。
3. 正式 API 只支持固定尺寸时：
   - 捕获图先适配到该固定尺寸；
   - 保持宝箱比例；
   - 使用统一留白；
   - Preview the Texture 使用相同的显示规则。
4. 本地 Mock 返回图必须与捕获图尺寸一致。
5. 结果显示采用与 Editing 预览相同的 Contain、居中和留白策略。
6. 不使用 UI 拉伸来掩盖不同宽高比。
7. 提示词用于强化构图约束，但尺寸一致性优先通过请求参数和图像处理保证，不能只依赖提示词。

### FR-08 生成前校验

生成前校验：

- 当前宝箱存在且可正常渲染；
- Editing 基本型参考图捕获成功；
- 文字、上传图、预设风格中至少存在一项；
- 上传图仍可读取；
- 当前没有其他生成任务；
- 目标输出尺寸有效。

校验失败时不进入加载状态，也不调用服务。

### FR-09 模态生成弹窗与取消

1. 点击 Generate Texture 后立即进入生成中状态。
2. 在主画面中心显示模态加载弹窗。
3. 弹窗至少包含：
   - 加载状态或动画；
   - “正在生成...”提示；
   - Cancel 按钮。
4. 弹窗显示期间，锁定弹窗以外的整个主界面。
5. Cancel 按钮在生成期间始终保持可操作。
6. 生成期间禁止：
   - 修改宝箱参数；
   - 旋转宝箱；
   - 切换 Editing 或 Preview the Texture；
   - 修改文字、上传图和风格；
   - 重复生成；
   - 下载。
7. 用户点击 Cancel 后：
   - 立即将当前任务标记为已取消；
   - 主动终止当前 Mock 或正式网络请求；
   - 忽略该任务之后到达的任何成功或失败回调；
   - 关闭模态弹窗；
   - 恢复主界面操作；
   - 保留用户文字、上传参考图和风格选择；
   - 保留生成前已有的有效 AI 结果；
   - 不自动切换预览模式；
   - 不显示为生成失败。
8. 成功、失败、超时或取消后均必须正确退出生成中状态。
9. 为防止旧任务覆盖新任务，每次生成使用唯一请求 ID，只有当前有效且未取消的请求可以更新界面。

### FR-10 本地 Mock AI 服务

本地 Mock 服务必须通过统一 AI 服务接口调用，UI 不直接依赖具体实现。

Mock 服务支持：

- 接收完整请求数据；
- 配置等待时间；
- 模拟成功；
- 模拟失败；
- 模拟超时；
- 响应取消并立即终止等待；
- 返回与 Editing 捕获图相同尺寸的本地测试图；
- 输出请求 ID、输入组合、提示词和尺寸日志。

建议默认成功结果直接基于 Editing 捕获图生成测试副本或测试处理版本，以验证尺寸、位置和模式切换是否对齐。

### FR-11 AI 二维结果展示

1. 生成成功后自动进入 Preview the Texture。
2. 将 AI 返回图直接显示为二维效果图。
3. 不将其设置为 3D 模型材质。
4. 显示区域不得包含额外 UI 截图内容。
5. 返回图应与 Editing 参考图保持：
   - 相同画布尺寸或宽高比；
   - 相同观察角度；
   - 基本一致的宝箱中心位置；
   - 基本一致的宝箱占画面比例；
   - 基本一致的外轮廓。
6. 新生成结果覆盖上一份结果。
7. 首版不提供历史记录。

### FR-12 生成失败

失败、超时或返回图片无效时：

- 关闭模态加载弹窗；
- 恢复界面操作；
- 显示可理解的错误信息；
- 保留用户文字、上传图和风格；
- 允许重新生成；
- 不用失败结果覆盖上一份有效结果。

用户主动取消不属于失败，不显示错误提示。

### FR-13 返回 Editing 的确认

存在有效 AI 结果时点击 Editing：

1. 显示确认对话框；
2. 建议文案：
   “继续编辑宝箱后，如实际修改参数，当前 AI 纹理预览将被清空。是否进入编辑模式？”
3. 提供 Confirm 和 Cancel。
4. Cancel：
   - 关闭对话框；
   - 留在 Preview the Texture；
   - 保留 AI 结果。
5. Confirm：
   - 关闭对话框；
   - 进入 Editing；
   - 暂时保留 AI 结果。
6. 没有有效 AI 结果时直接进入 Editing，不弹窗。

### FR-14 参数修改后的结果失效

1. 进入 Editing 本身不会清除 AI 结果。
2. 用户首次实际修改任意宝箱结构或尺寸参数时，AI 结果失效。
3. 只有值真正发生变化才算修改；输入相同值或取消输入不触发失效。
4. 结果失效后：
   - 清除 AI 二维效果图；
   - Preview the Texture 恢复默认预览；
   - 保留文字、上传参考图和风格选择，便于重新生成。
5. 旋转视角不使 AI 结果失效，也不自动清除 AI 结果。
6. 如果用户希望 AI 结果匹配新的旋转角度，由用户主动再次点击 Generate Texture。

### FR-15 Download JPG

1. Download 与是否生成过 AI 无关。
2. 当前预览区域中存在可见宝箱时，Download 可用。
3. 导出内容为当前预览区域中的宝箱画面：
   - 当前显示默认 3D 宝箱时，导出默认 3D 预览；
   - 当前显示 AI 二维效果图时，导出 AI 效果图；
   - 当前显示其他有效宝箱预览时，导出当前实际显示内容。
4. 导出内容只包含预览画面，不包含按钮、Texture Panel、加载遮罩等 UI。
5. 文件格式固定为 JPG。
6. JPG 应使用高质量编码。
7. 保存成功后显示保存路径或成功提示。
8. 保存失败时显示错误原因。

保存位置和命名规则仍需最终确认。本地阶段建议：

- 默认目录：`Application.persistentDataPath/Exports`；
- 默认命名：`chest_preview_yyyyMMdd_HHmmss.jpg`。

### FR-16 运行时状态

系统至少维护：

- 用户文字；
- 上传参考图；
- 当前风格；
- 当前系统约束提示词；
- 当前最终提示词；
- 当前宝箱参数快照；
- 当前视角快照；
- 当前生成任务状态；
- 当前请求 ID；
- 当前请求是否已取消；
- 当前 AI 二维结果；
- AI 结果是否有效；
- 当前实际预览内容；
- 最近一次错误；
- 当前预览模式。

AI 状态、UI 控制器和服务实现应解耦。

## 10. 非功能需求

### NFR-01 服务可替换

UI、业务流程、本地 Mock 和正式 API 客户端通过统一接口解耦。

### NFR-02 资源安全

- 防止重复提交；
- 正确处理中断和对象销毁；
- 释放临时 RenderTexture 与 Texture2D；
- 捕获、读取和保存均进行异常处理。

### NFR-03 可测试

Mock 的等待时间、成功、失败、超时、取消和返回图可配置。

### NFR-04 可诊断

开发日志记录请求 ID、输入组合、最终提示词、输入输出尺寸、状态变化和失败原因，不记录未来 API 密钥。

### NFR-05 视觉一致

Editing 参考图、Mock 结果、AI 结果和 JPG 导出使用统一的画布尺寸、宽高比、居中方式和留白策略。

## 12. 首版本验收清单

### AC-01 Editing 参考图

在任意用户旋转视角点击生成，请求中的 Editing 彩色截图与用户当前看到的宝箱角度一致，并且不包含 UI。

### AC-02 全部输入组合

文字、上传图和预设风格可以分别单独使用，也可以任意组合；三项全部为空时不能提交。

### AC-03 双参考图职责

存在上传图时，请求同时包含 Editing 基本型参考图和上传纹理参考图，二者不会互相替代。

### AC-04 风格占位

风格浮层包含 No Style、硬核科幻和卡通，单选状态与附加提示词正确。

### AC-05 构图约束

最终提示词包含保持视角、轮廓、位置、大小和画布比例的系统约束。

### AC-06 同尺寸结果

Mock 返回图与 Editing 捕获图像素尺寸一致，并在 Preview the Texture 中使用相同显示规则。

### AC-07 模态锁定

生成期间画面中心显示模态加载弹窗。除 Cancel 按钮外，整个主界面无法操作，也无法重复提交。

### AC-08 二维展示

Mock 成功后自动进入 Preview the Texture，直接显示二维结果，不修改 3D 模型材质。

### AC-09 失败恢复

失败或超时后弹窗关闭、输入保留、界面恢复操作，并允许重试。

### AC-10 取消生成

点击 Cancel 后任务被终止，弹窗关闭，主界面恢复，输入和生成前已有结果均保留；被取消任务的迟到回调不能更新预览或弹出错误。

### AC-11 Editing 确认

有有效 AI 结果时点击 Editing 弹出确认框。取消时保留结果；确认时进入 Editing 但不立即清除结果。

### AC-12 实际修改失效

只有宝箱结构或尺寸参数值真正发生变化时，旧 AI 结果才清除；仅进入 Editing、提交相同值或旋转视角均不清除。

### AC-13 旋转后主动重新生成

用户旋转宝箱后旧 AI 结果保持有效；用户再次点击 Generate Texture 时，新请求捕获并使用新的当前视角。

### AC-14 任意预览下载

无论当前是默认 3D 预览还是 AI 二维效果图，只要预览区域存在宝箱，均可导出为不含 UI 的有效 JPG。
